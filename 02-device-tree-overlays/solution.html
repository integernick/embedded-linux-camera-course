The boot entry

  • Reference blocks are in extlinux-labels.conf, one for the IMX477 and one for the virtcam entry of Step 6.
  • Requirement 1: DEFAULT imx477-a at the top of the file.
  • Requirement 2: the APPEND line copied verbatim from the board's own working primary entry, with only the marker added.
  • Requirement 3: an FDT path that names an existing file, the -nv DTB whose first compatible string equals the one of the running board.

  • The stock primary label stays unchanged as the fallback entry on the serial console.

Step 3 — expected verification results

Expected form after the reboot, (verified-on-target: pending):

  • grep -o 'course_label=[^ ]*' /proc/cmdline prints course_label=imx477-a. Any other answer means that UEFI booted a different label. Check DEFAULT first.
  • find /proc/device-tree -name '*imx477*' lists /proc/device-tree/bus@0/cam_i2cmux/i2c@0/rbpcv3_imx477_a@1a and four /proc/device-tree/__symbols__/rbpcv3_imx477_* property files.
  • Those four are the overlay's labels, kept because overlays and base are compiled with -@.
  • status of the sensor node reads okay. ls /dev/video* shows /dev/video0, the node that the overlay requests with devnode = "video0".
  • sudo dmesg | grep -i imx477 shows the probe and a tegra-camrtc-capture-vi tegra-capture-vi: subdev imx477 9-001a bound line. The bus number depends on the board.
  • i2cdetect -l | grep mux shows two adapters with parent i2c-2, which is cam_i2c. Both read chan_id 0 under the -A overlay, and the sensor is on the first, bus 9 (lesson section 7).
  • A scan of bus 9 shows UU at 0x1a: the driver is bound.
  • If the node exists with status okay and /dev/video0 is missing, the DT layer is correct. The problem is one layer below: ribbon seating or the wrong connector.

  • Thirty-one warnings, none of which stops the write.
  • Page 4 summarizes five differences between the source and the decompile. This section shows them in full. The lab does not ask for them.
  1. cpp macros became bare numbers.
    • mux-gpios = <&gpio_aon CAM_I2C_MUX GPIO_ACTIVE_HIGH> became mux-gpios = <0xffffffff 0x13 0x00>.
    • CAM_I2C_MUX = TEGRA234_AON_GPIO(CC, 3) = 2 × 8 + 3 = 19 = 0x13, and GPIO_ACTIVE_HIGH = 0.
    • reset-gpios became <0xffffffff 0x3e 0x00> in the same way.
    • The preprocessor ran before dtc, and the blob stores only cells.
    • compatible = JETSON_COMPATIBLE_P3768; became one string list with ten nvidia,p3768-0000+p3767-000X entries, five of them -super, separated by \0.
  2. External label references became 0xffffffff sentinels plus __fixups__.
    • i2c-parent = <&cam_i2c> became i2c-parent = <0xffffffff>.
    • The end of the decompile gained a relocation table:

        gpio_aon = "/fragment@0/__overlay__/bus@0/cam_i2cmux:mux-gpios:0";

        gpio = "/fragment@0/__overlay__/bus@0/cam_i2cmux/i2c@0/rbpcv3_imx477_a@1a:reset-gpios:0";
    };
  • Three fixups form the overlay's complete list of references to the base tree: the AON GPIO controller, the camera I2C controller, the main GPIO controller.
  1. Label definitions became __symbols__ entries, the effect of -@.
    • The four endpoint labels are removed from the nodes and appear as fragment-relative paths:

  • The four remote-endpoint references between those labels are internal to the overlay.
  • They got real phandles plus __local_fixups__ entries, one per remote-endpoint property, instead of sentinels.
  1. Phandles became explicit.
    • Nodes that are referenced got phandle = <0x01>-style properties.
    • The numbers reflect allocation order and carry no meaning. A diff of two builds on phandle values shows only noise.
  2. Formatting is gone.
    • Comments are removed, all integers print as hex, the include is flattened, and the node order is canonical: 318 output lines against 312 source lines.
    • The hog's gpios = <CAM1_PWDN 0> reads <0xa0 0x00>, and its label reads "cam1-pwdn".

Design notes

  • &gen8_i2c resolves because the base DTB's __symbols__ maps gen8_i2c to /bus@0/i2c@c250000, the 40-pin header bus.
  • That bus is enabled with okay in the devkit's common dtsi and fixed as /dev/i2c-7 by the i2c7 alias.
  • The #address-cells/#size-cells pair is in each fragment. A one-cell reg needs one-cell addressing declared by its parent, and the parent is not in the file.
  • The mux node has a second pair for its own child, and the child has a third for the sensor.
  • No driver claims the two compatibles, by design. The nodes must appear in the tree and do nothing.
  • The labels practice_mux_i2c0 and practice_cam exist only because dtc runs with -@.

Step 5 — on-board results and the three observations

Expected board state after adding the two practice dtbos to OVERLAYS, mux before cam, (verified-on-target: pending):

  • /proc/device-tree/bus@0/i2c@c250000/mux@70/i2c@0/cam@1a/ exists with compatible = jetson-course,practice-cam and status = okay.
  • /sys/bus/i2c/devices/7-0070 exists and has no driver link.
  • No /sys/bus/i2c/devices/ entry exists for the cam.
  • /dev/video0 is still present.
  • sudo i2cdetect -y -r 7 shows -- at 0x70, because nothing answers there and no driver holds the address.

The three observations:

  1. A DT node is a declaration, not a detection.
    • The kernel holds mux@70 and cam@1a although no device answers at either address.
    • Device tree describes what the integrator declares to exist. The course's virtcam depends on this property from Lesson 08 on.
  2. A node becomes a device only where a bus driver processes it.
    • The I2C core registers a client for every addressed child of an adapter that it registers. mux@70 under bus 7 therefore became 7-0070.
    • No of_match_table contains jetson-course,practice-mux, so no probe ran. That is the matching chain of Lesson 01 with the driver missing.
    • cam@1a got no client at all. Its parent i2c@0 becomes an adapter only if a mux driver probes mux@70.
    • The real cam_i2cmux works the same way. Its channels appear as buses 9 and 10 only after the i2c-mux-gpio driver has bound.
  3. Overlays combine freely when their targets are disjoint, and in dependency order otherwise.
    • The stock overlay modifies /, the practice mux modifies gen8_i2c, and the practice cam modifies a node that the mux created.
    • The position of the stock overlay in the list is free. The relative order of the practice pair is not.
  • Cleanup: remove the two /boot/course/practice-* entries from the OVERLAYS line and reboot.
  • The imx477-a label stays as DEFAULT, because Lesson 03 starts from a working /dev/video0.

Mechanical verification

  • verify-build-jp7.sh checks the container-side claims of the lab and of the lesson on every run. It runs inside jetson-build-jp7, with TREE at the pristine r39.2.1 tree and SOLDIR at this directory.
  • It compiles the practice pair through the cpp + dtc -@ pipeline against the r39.2.1 dt-bindings.
  • It applies mux then cam onto both r39.2.1 base DTBs. It asserts that the cam node is at /bus@0/i2c@c250000/mux@70/i2c@0/cam@1a, and that cam then mux fails with FDT_ERR_NOTFOUND.
  • It asserts the label counts that the lesson state: 699 in the base blob, 702 after the practice pair, and 703 after the stock overlay.
  • It asserts that the 312-line source decompiles to 318 lines with 31 warnings.
  • It applies the stock overlay and asserts the resolved mux-gpios and reset-gpios cells, and the unused gpio@6000d000 node without a compatible.
  • It stacks imx477-A with imx477-C and asserts that num-channels stays 1 with one VI port that points at port index 2, while imx477-dual has 2.
  • It checks the source facts: the 22-pin header string, no bandwidth properties, and the one-pin hog. It also checks both model strings and the -@ in the overlay Makefile.
  • It compiles the three toy files of examples/ and asserts every transcript that the lesson print. That covers the toy merge, the cpp expansion, the endpoint phandles and the mux references.
  • verify-build-rpi.sh checks the Raspberry Pi parts of the sections against the pinned Raspberry Pi tree. It asserts the label counts, the fixups of the camera overlay, and the result of fdtoverlay.
  • Neither script writes into the trees, and neither depends on another lesson.
